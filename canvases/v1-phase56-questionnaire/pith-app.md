# pith 是给谁的：Pith App 的背景

给做 Pith 视觉的 Agent 看的背景。Pith 的会话 2026-11-16 写了第一版；2026-11-22 本仓库的会话读了 Pith 仓库、站主认了新架构以后，照新架构改了这一页（架构的全文在仓库根的 `HANDOFF.md` 第 1–5 节）。事实写全在这里，不用、也别去 Pith 仓库找（`CLAUDE.md`「权限边界」：各项目互相独立）。站主的感觉和要求以验收问卷第 1 页和站主后来的话为准。

## Pith 是什么

- 站主自己的话（第 1 页）：Pith 是站主的**数字花园**，帮站主对一个领域深入探索、做研究，沉淀出通俗、真实、可视化的知识资产，长成自己的知识体系。
- 背后的事实：一个 macOS 桌面工作台，只有一个用户。用户是研究生，文献以英文为主，用它写毕业论文、做日常事实调查、读书学习。名字 Pith 取「要旨、精髓」的意思。
- 本地优先的桌面 App（Tauri 2：React 前端 + Rust + SQLite）。界面全中文；Word 里的「Pith」选项卡、按钮、对话框是英文。
- 用的时候常常连着看几个小时的文字：英文原著和中译并排读、看引文。所以正文要好读；动效是站主要的亮点，放在交互和反馈上，别打扰读字。
- **程序不限制模型**（站主 2026-11-22）：回答就是普通的文字，引了的地方带编号 [1] [2]，点开看原文。不再给句子分类，界面上不用画「原文、他人、解释、推演」这些记号。
- 气质：淡雅、简约、灵动，不要科技感、学术味、机械感（第 1 页）。**大气、简约**（站主 2026-11-22）：不要罗列一堆功能栏、参数、按钮；能用自然语言就用自然语言，能用 `/` 呼出就不用按钮。

## 这一轮的方案管什么

- **管 App**：窗口里的全部界面；导出的报告和卡片（HTML）；App 图标。Word 选项卡上的图标可以以后再说。
- **不管 WonderLab 作品本身**：WonderLab 是对话里的一个技能，模型给一个问题现做一件能交互的 2D / 3D 小作品。作品的视觉另起方案，叫 `pith-wonder-<名字>`、「Pith Wonder - <名字>」，和 App 的分开，这一轮不做；对话里装作品的那张交付卡归 `pith`。
- 方案名就叫 `pith`，Design System 叫「Pith」。

## 界面的结构（2026-11-22 定）

竖栏四个入口：**对话**（首页）、**知识库**、**文献库**、**设置**。

| 入口 | 里面是什么 |
| --- | --- |
| 对话 | 打开 Pith 就是这里：一句问候、一个大输入框，别的不摆。左边是对话列表（可以收起）。一个对话绑一个角色，顶上是角色名。问了以后：一行短状态说刚才做了什么（「找了 6 段，读了 3 段」）；回答是普通文字带编号，点开编号旁边展开那一段原文，再一步回到文献库那一条；成果（概念卡、调查报告、WonderLab 作品、Word 修订预览）是交付卡，能打开大图、存进知识库；要站主定的事是问题卡（单选、多选、带推荐）；长任务是任务卡；三步以上的任务在输入框上方列待办 |
| 知识库 | 一个个知识库（例：「毕业论文」「读《国富论》」）和里面的材料：解析出的全文（带段落号、页码）、摘抄、笔记、网页快照、成果。一份材料能在几个库里。一个列表、一个详情；加材料、整理都在对话里说 |
| 文献库 | 只管「这是哪篇、文件在哪」：集合、标签、文献列表、详情（元数据、附件）；PDF 阅读和标注，八种颜色；Zotero 导入、联网补全。选一段原文能直接问 Pith |
| 设置 | 七页：角色、技能、知识库与检索、模型与费用、Word 与引文、数据、外观。角色页每个角色一页：一张名片（头像、名字、一句话专长、「开始对话」）、一段说明、三行设定（默认知识库、偏好模型、常用技能），下面是和它的对话 |

输入框里三个符号：`/` 点名技能（`/调查`、`/概念`、`/润色`、`/画`），`@` 请一个角色答这一回（`@审稿人 这段站得住吗`），`#` 选这次用哪几个知识库（选了留成输入框里的小标签）。别的都说话。按钮只剩要站主拍板的地方：问题卡的选项、Word 修订预览上的「应用」。

四个初始角色：**Pith**（研究助手，默认）、**伴读**（读一本书时陪着读、反问、做概念卡）、**审稿人**（查出处、找反例、唱反调）、**编辑**（守学校规范和引文、润色 Word）。每个角色要有能认出来的头像。

原来竖栏里的「排版」「调查」「概念」三个页面拿掉了，变成对话里的技能，不用画。

## 现在代码里的样子（接的时候参考）

- 竖栏宽 64px，18px 的 Lucide 图标下面一行 10px 的字；侧栏宽 240px。
- 字：正文 13px，行高 1.6。字体是系统的 PingFang SC（`-apple-system` 兜底），等宽用 SF Mono。
- 颜色跟着系统切浅色、深色。没有组件库，Tailwind v4 加 CSS 变量；图标是 Lucide。

这些是现状，不是要求：新架构下竖栏只剩四项，首页是对话，尺寸照你的方案定。

## 接进 Pith 时怎么对上（V2，由 Pith 的会话做）

挑中的那版发版以后，Pith 把 `tokens.css` 之类同步进自己的 `src/vendor/pith/`，再把下面这些变量的值换成你的。方案里最好有对得上这些名字的颜色角色，名字可以不一样，但要在 `DESIGN.md` 写清哪个对哪个：

- **Pith 现在就有的**（shadcn 命名）：`--background`、`--foreground`、`--sidebar`、`--card`、`--border`、`--muted`、`--muted-foreground`、`--primary`、`--primary-foreground`、`--accent`、`--accent-foreground`、`--destructive`、`--ring`。
- **现在写死、接的时候要收进变量的**：成功（现在用 Tailwind 的 emerald）；提醒（现在用 amber）。
- **新架构要的**：引用编号和点开后的原文高亮；问题卡、交付卡、任务卡；`#` 知识库标签；角色头像。
- **不换的**：PDF 标注的八种颜色和 Zotero 一样（黄 `#ffd400`、红 `#ff6666`、绿 `#5fb236`、蓝 `#2ea8e5`、紫 `#a28ae5`、品红 `#e56eee`、橙 `#f19837`、灰 `#aaaaaa`），从 Zotero 导进来的标注要对得上。你的颜色在这八种旁边也要好看。
- **一定要守的**：浅色、深色都要，APCA 照核心约定 9（探索页只提示，建方案必须过）；中文为主的界面，小字也要清楚；打包的字体只用系统字体或可再分发许可的字体。

## 第一轮画什么

照 `skills/design-craft`：2–4 个真正不同的低保真方向，每个方向画通同一条任务（`HANDOFF.md` 5.2）：打开就是对话 → `#` 选「读《国富论》」、问一个问题 → 回答带编号、点开看原文、回到文献库 → 存成概念卡 → `@审稿人` 或在角色页改说明。要露出来的屏：对话（空状态、问了以后）、知识库、文献库、角色页，宽 1280、高 800。可以写这些书：Adam Smith *The Wealth of Nations*、斯密《国富论》、Stavrianos *A Global History*，再加几篇讲 political efficacy 的英文论文。
