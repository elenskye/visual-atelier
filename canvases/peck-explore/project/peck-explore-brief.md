# Peck 探索简报

Peck 视觉探索的简报：需求、站主的话、分几步、每轮做什么和结果。照 Pomelo Explore 的走法：一步一页，每页站主验收了才走下一步。这是过程记录；成型后的规则写进 Peck 方案的 `DESIGN.md`。

- 画布：Peck Explore（这块画布，现用账号）。**整个探索只在云端画布上做**（站主 2026-11-09 定）：样稿、生成器（`project/src/`）、这份简报都在这里；成型、并且有了 Peck 的 Design System 以后，再一起导入 visual-atelier。
- 第一版（2026-11-08，「初版（对照）」页）站主退回：效果一般，像 VSCode。
- **已导入 visual-atelier（2026-11-10，收尾）**：画布的本地源在 `canvases/peck-explore/`（生成器、全部画板、附件 `blobs/`），方案在 `schemes/peck/`（0.1.0 approved）。以后改动先改本地、再发回这块画布。

## 不再询问

- 名字 Peck。只在站主自己的 Mac 上用，不分发。
- 问卷（2026-11-08）定了的：CLI 为主；CLI 模式 / API 模式两种界面；三栏（项目和任务 · 对话 · 改动）；打开先看项目列表；发任务 = 一句话 + 谁来干；跑完默认留着，一键撤销整个任务；权限三档 + 高危弹卡片 + 所有模型能 ASK；IBM Plex；舒适的疏密；跟随系统明暗、明暗都做；中文为主、专有名词保留英文。
- 青色 `#00E5FF` 是主强调色。
- 不取用 Pomelo、Vermilion 的 token、规则和资产。不用 Rive，不做声音。
- 演示内容都是编的（`weather-cli`、`notes-sync`、`pomelo-site`），不是站主的真实项目。
- 第 1 步第一轮定了（2026-11-09）：方向 C 点阵终端；配色 P3 深海；动效 M4 点阵为主，M3 的「在跑」和 M1 的扫描做点缀；App 图标都从现在的图标出发。
- ASK 学 Claude Code：一张卡装得下很多信息，有选择题和判断题；要用到的权限放进同一张卡一次批，不一条条问。
- 第 1 步第二轮定了（2026-11-09）：主样板、ASK 卡片、动效融合都认了。四个细节：角用像素阶梯角，底纹用 LED 点阵孔，发光用强，点阵字（Doto）连标签和按钮也用（标签、按钮改英文大写）。
- App 图标两个都留，设置里能换：J2 像素重绘，和现在的图标（只润色背景，鸟不动）。
- 第 1 步第三轮定了（2026-11-10），第 1 步收尾：现在的图标用 A3（渐变 + 光 + LED 点阵孔）；浅色的青用 L2 深青（填色 `#007A94` 白字、进度块 `#0099B8`）；界面字体用 F2（名字用缝合像素 12，说明用 Plex Sans + 苹方，代码用 Departure Mono；数字、标签、按钮用 Doto）。零件的像素角、设置里换图标的样子都认了。
- 第 2 步第二轮定了（2026-11-10）：权限三档叫 PLAN / EDIT / AUTO（默认 EDIT）；AUTO 时装依赖、联网不问，删文件、改项目外的文件还是问；代码可以用 Departure Mono 11，是「字号不小于 12」唯一的例外。规则第一版和迁移测试画的界面没提意见，按认了往下走。
- 右栏做成四个能切的模块（站主 2026-11-10 加的）：CHANGES（原来的改动）、ONE SHOT（边开发边提问）、FILES（预览项目文件）、TERM（跑终端命令）。
- 第 2 步第三轮定了（2026-11-10）：单次请求挪进 ONE SHOT（API 模式的「谁来干」只剩单模型干活、规划 + 实施）；ONE SHOT 用 API 和 CLI 都能答，能读项目、不能改；模型在跑任务时终端锁着，站主不能在终端里改。
- 第 2 步第四轮定了（2026-11-10），第 2 步收尾：发任务时终端还在跑的命令接着跑、STOP 一直能点，它改的项目文件算进这次改动；ONE SHOT 默认谁来答跟顶栏的模式，换了就记住；PLAN 档的任务也锁终端。权限三档、右栏四个模块、ONE SHOT、终端锁、API 模式「谁来干」两种已写进 Peck 的 `docs/design.md` 和 `docs/roadmap.md`。
- 第 3 步第一轮定了（2026-11-10），第 3 步收尾：深色为过 APCA 亮一档认了；键盘焦点画成控件里面一圈青点线认了；App 图标的底板保留第 1 步的比例（占画面 7/8，鸟占底板 2/3），不照 Apple 的格子。
- 小尺寸 App 图标（2026-11-10，第 4 步做的时候）：第一版借菜单栏的 16 格鸟，站主说脸太臃肿；重画成照 J2 缩的 28 格鸟（128、64、32）和 14 格鸟（16），喙张开、脖子细。底板 7/8 时每个尺寸一格都是整像素。
- Design System 叫「Peck」，在现用账号的云端（https://claude.ai/artifact/KpUihg5AHn6cw1ggNTx6s1）；第一主题深色；组件都是 HTML + `pk-` 类名，没有 JS 组件；源在 `project/scheme/design-system/`，生成器 `src/s4/`。
- 收尾定了（2026-11-10）：Design System 认了；菜单栏模板图换成 14 格的鸟（和 16 像素 App 图标同一只，一格 1pt）；方案 0.1.0 和全部资产改 approved，A3 收进方案的 `marks/raster/`。

## 我的理解（等站主认）

- 「像 VSCode」来自：一层层灰色面板 + 1 像素分隔线 + 满屏等宽字 + 青色只剩几个小点。新方向要换掉这套骨架感：底色有自己的性格（点阵、冰白、纯黑），青色是全屏唯一会发光的颜色，配色只用浅而干净的辅助色。
- 「锐利」：深色里青色只用纯 `#00E5FF`，是发光的线和点。浅色里纯青当荧光笔底色太跳（第二轮站主说违和），第三轮浅色换成深一点的青，和墨色、冷白放在一起不抢。
- 「亮眼的动效」：每个方向有自己的招牌动作，放进真实场景（发任务、在跑、完成）里看，不做装饰性的循环。
- 动效融合（第二轮）：点阵管出现、消失和进度，位移按格子一跳一跳地走；弹扣只给正在跑的那一步；扫描在发出、等你、完成、撤销时各扫一次，同一时刻只有一道。
- 字体（第三轮）：点阵字 Doto 已经管数字、标签、按钮；剩下的「名字」（任务名、步骤名、问题、选项）、「说明」、「代码」三种字要跟像素风一致。中文像素字用缝合像素 12 格（只用 12、18、24 号才清楚），代码用 Departure Mono（11 格）。名字用像素字、说明留光滑字，读长段不累。两个字体都是开源（OFL），站主 11-09 同意下载，作为附件传在这块画布上；以后能打包进 App。
- 浅色的青（第三轮）：深色不动；浅色推荐 L2 深青（填色 `#007A94` 白字、进度块 `#0099B8`），另摆 L1 柔青、L3 墨底青光。
- 图标（第三轮）：现在的图标润色是把鸟从原来的纯色底里分出来（边缘按颜色反算透明度，眼睛算鸟的一部分），放到新底上，鸟一个像素不动。
- 外框（第 2 步第一轮）：左栏是项目和任务（每个项目带最近几次任务，NEW TASK 在最上），底下是这个任务的记录（存快照、批过的、问过的、做完、撤销）；中栏是新任务和对话（一句话 + 谁来干 + 权限；发出以后是你的话、任务进度和卡片）；右栏是改动（快照、文件、Diff、撤销）。顶栏只剩品牌、项目、CLI/API、设置。高危的事在规范写好以后一张卡一次批；跑的时候有问题再停下来问；做完默认留着，撤销前在右边确认一次。
- 右栏（第 2 步第三轮）：顶上一条页签，四个模块一次开一个，切走以后页签上说那边有新东西，从不自己切走；每个模块都能展开到宽栏。ONE SHOT 就是 roadmap 里的「单次请求」（第三轮站主定了挪过来）。FILES 只看不改，改过的文件标法和 CHANGES 一样。TERM 是站主自己的终端，不经过权限三档、不进模型上下文。模块之间只靠「带上」和「跳过去」连。
- ONE SHOT 和终端（第 2 步第四轮）：ONE SHOT 谁来答在左下的选项片里选，弹一个菜单，CLI 一组（Muse、Grok，用 PLAN 档跑、走订阅额度）、API 一组（配了 Key 的模型，只给读文件的工具、按次算钱）；默认跟顶栏的模式，换了就记住。它能读整个项目，回答上写读了哪些文件；任务进度和终端输出它看不到，还是用 + 带上。终端在模型跑任务时锁着：从发出到做完，等你批、等你答、撤销的时候都算；输入行和页签各一把锁，输出照样能看、能带去 ONE SHOT；发任务前就在跑的命令接着跑，STOP 一直能点。做完解锁，之后改的文件不算进任务，撤销不动它们。
- 方案（第 3 步第一轮）：定值都在一份源里（`src/s3/tokens.mjs`），画板从它取值，同一份写成方案文件 `project/scheme/`（照 visual-atelier 的 `schemes/<方案>/` 格式：tokens 五个、fonts、marks、DESIGN.md），导入时整个复制成 `schemes/peck/`。对比度门槛比 Vermilion 的 75 / 60 高（正文 90、说明 70、提示 55、青字和状态字 60），因为 Peck 的字只有 12–12.5 号；只改过不了的几处，都在深色。动效一格 50ms、时长都是整格。键盘焦点画在控件里面（一圈青点线），因为像素阶梯角会把外面的光圈切掉。App 图标照 Apple 的格子：鸟按 32 格画，底板内缩 3 格，每个尺寸都是整像素（站主没选，保留第 1 步的比例）。
- Design System（第 4 步第一轮）：照 visual-atelier 的 `schemes/<方案>/design-system/` 写源（system.json、tokens.config.json、README、bundle.css、18 个组件），用 visual-atelier 的 build:ds 的函数出云端的文件。比 build:ds 多四件，导入时要补进 build:ds：第一主题深色、`fonts/` 两个字体文件、size 和 step 两组 token、没有圆角就不出 radius。挂到画布照 Design 画布的做法（`project/ds/peck/` + `designSystems` 一条），S4 的画板只引它，不带自己的控件样式；S4-Kit 和第 3 步的控件板一格一格截图比（两边行高钉成同样的整数、错开 1 像素以内）。
- ASK（第二轮）：问题卡占住输入框的位置，答完输入框才回来；单选带说明和「推荐」、选了会怎样写出来，多选、判断题、最后核对再提交；回答里要用到的权限在核对页一起批。高危操作的权限默认不勾，勾上要再确认。

## 分几步

| 步 | 内容 | 站主定什么 |
| --- | --- | --- |
| 1 图形语言（1–2 轮） | 三个方向摆同一套内容；配色四套明暗都摆；动效四种性格 × 三个场景；App 图标六个方向 | 方向（可混）、配色、动效性格、图标方向 |
| 2 外框小样（2–3 轮） | 用选定的语言做能点的三栏小样：项目列表、发任务、在跑、完成、撤销、ASK 和高危卡片；动效接进真实流程。定稿后写成规则，再做迁移测试（设置、额度页、空状态、加载这些没画过的，只照规则做） | 外框、交互、规则认不认 |
| 3 方案 | 色板明暗定值过 APCA；控件全套；动效数值；App 图标各尺寸和菜单栏模板图定稿 | 方案认不认 |
| 4 Design System | 在云端新建「Peck」Design System（说明、组件预览、封面），挂到这块画布上对一遍 | Design System 认不认 |
| 收尾 | 画布、方案、Design System 一起导入 visual-atelier（`canvases/peck-explore/`、`schemes/peck/`）；站主打 tag 后同步进 Peck；Peck 的 Phase 2 完成 | 打 tag |

## 每轮怎么收

- 每轮一页（2026-11-13 起页名照 visual-atelier 的 Explore Deck 规矩写「探索 N · …」「优化 · …」，外框小样只留第四轮和前两轮独有的板）；画板文件名带步号和轮次（`S1-…`、`S1b-…`、`S1c-…`、`S2-…`、`S2b-…`、`S2c-…`、`S2d-…`、`S3-…`），不重复。外框规则存在 `project/peck-rules.md`（现在是第三版）；第 3 步起方案文件在 `project/scheme/`，第 3、4 步照它。
- 每轮结束在下面的日志记一行：做了什么、站主选了什么、淘汰了什么和原因。
- 生成器在 `project/src/<步>/`，画板由它生成，不手改。
