# 简报模板

一轮视觉探索开工前，照这份把简报写全（`design-craft`「输入」）。可以直接写成一份 Markdown，也可以把下面的问题做成问卷页（`questionnaire`）。站主没写到的项，用提问功能问，别自己替站主定。

## 1. 是什么、给谁用

- 产品或作品是什么，一句话（用站主自己的话）。
- 谁用、在什么情况下用、一次用多久（例：「一个人、在 Mac 上、连着读几个小时英文文献」）。

## 2. 用在哪

- 平台和尺寸（macOS 窗口 1280 × 800、手机、网页、PPT、导出的卡片……）。
- 明暗：都要、只要一种，还是跟着系统。

## 3. 气质

- 多一点什么、少一点什么（各两三个词）。
- **把形容词翻成看得见的东西**：每个词配一个具体的例子（「灵动 = 选中一条时有东西长出来，不是每个按钮都弹」）。

## 4. 参照

- 具体的参照：一个网站、一件作品、一个物件、一本书的版式。写清楚取它的什么（「取它的留白和小动效，不取它的配色和插画」）。
- 参照只取感觉，不抄图形、插画、字体和文字。

## 5. 反例

- 不要像什么：具体的产品或风格（例：「不要像 VSCode」「不要像学术软件」）。

## 6. 要避开的默认

从 `design-craft`「点名默认惯性」那张清单里勾出这一次一定不要的，或者明确说「这一条可以用，因为……」。

- [ ] 米色、旧纸的底配衬线标题和陶土色点缀
- [ ] 苔绿和直接画成植物的「生长」隐喻
- [ ] 每栏一样密的三栏骨架
- [ ] 圆角卡片加左边彩条
- [ ] 渐变、光晕、玻璃、发光
- [ ] 满屏的小动效
- [ ] emoji 和没人要的数字、徽章

## 7. 真实内容和任务

- 一条真的任务：从哪里开始、做什么、到哪里结束（例：「从文献库选一段原文 → 在对话里问 → 看到证据和出处 → 存成卡片」）。
- 真实的内容：书名、数据、文字。缺的写成 `[待填]`，别让 Agent 编。

## 8. 第一轮交什么

- 默认：2–4 个真正不同的方向，低保真（灰阶加一个强调色、一两种字体、真实内容），每个方向一屏或一张能点的板，加一句话、押注和代价。
- 第一轮**不交** token、Design System、动效零件和质检；方向挑定以后再做。

## 9. 约束

- 字体许可（只用可再分发的，或系统字体）、对比度（探索只提示，建方案必须过 APCA）、要对上的变量名、产物预算。
- 不能碰的内容（私人内容、真实数据）。

## 10. 怎么评

- 站主怎么挑：说代号就行，可以拼（「B 的骨架 + A 的配色」）。
- 评估的人先遮住颜色看骨架，再看押注和动效（`design-craft`「评估几家的版本」）。
