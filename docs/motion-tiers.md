# 动效档位

两档，所有动效必须标明：

| 档位 | 性格 | 默认用在哪 |
| --- | --- | --- |
| `calm` | 克制、安静，服务阅读与状态反馈 | 阅读页、列表、控件状态 |
| `expressive` | 更大方、有记忆点，服务「时刻」 | 首屏、入场、站主主动触发的交互、PPT 与动图 |

## 共同底线（两档都必须满足）

- `prefers-reduced-motion: reduce` 时回到静态终态：无位移、无过渡，循环停止。
- 键盘与读屏路径不依赖动效。
- 动效的实现与 GIF 来自同一份源。

## 数值由方案自己定

仓库层只规定档位的含义，具体数值写在各方案的 `tokens/motion.json`，规则写在该方案的 `DESIGN.md`。

## 为什么分档，而不是删规则

大动效集中在少数时刻才有记忆点；阅读页保持安静才不累。分档让「更大方」与「可读、可访问」同时成立。
